## Verified facts that carry the design
- **F1 raw window is already bounded to ~2 d (phase-dependent):** `slide_drop` (`window_store.py:429-442`) runs in `run_build_cycle` (`scan.py:2353`; cutoff computed at `:2413-2416` from `t0`/`tick`/`Dt`; the `slide_drop` call is `:2684-2686`) only for registry pods in scope (`:2418-2427`) and only after a clean fetch (a fault `continue`s first, `:2606-2610`, `:2635-2641`). In-scope streams therefore hold approximately two days: the cutoff is the refit boundary
`fit_start = t0 - tick - Dt`, and the active span grows within each refit cycle as ingest advances
the newest timestamp (the cutoff only advances on refit); counter metrics carry extra
`counter_max_gap_s` headroom ahead of `fit_start` (R-P6 observed ~2.007 d). **No valid TTL ever trims them**; the TTL is the only bound for streams `slide_drop` never revisits (pod/metric out of scope or config, faulting fetch, `Dt` lowered). Keeping 7 d of raw would need `slide_drop` changed (scan.py) — NOT P6 (Q2).
- **F2 lock model:** one WAL connection per store (`open_solo_connection`, `window_store.py:70-104`, `check_same_thread=False`, busy timeout `persistence.sqlite.timeout_seconds`=30 s), each behind its own `RLock` (`:116-132`, `state.py:50-70`); window+state stores share ONE file (`driver.py:122-189`). Writers: `SoloRuntime` thread (ingest/refit, `driver.py:2206`), exporter/handler threads (`handle_solo_request`), 4 build-pool workers. SQLite has one writer; its busy handler is unfair (measured below).
- **F3 per-metric values exist at score time:** `driver._score_all_metrics` (`driver.py:1267-1405`) fills `metrics_out[name]` = `{p, ess, reason, model_t0, model_age_seconds, model_method,…}`; `_public_metrics` (`:1962-1967`) strips `_ring`/`unready`. `m["ess"]`/`model_age_seconds`/`model_method` come from the model snapshot that actually scored (`:1340-1345`).
- **F4 served model age is always < `dt`:** `_scorable` rejects a model unless `m0 <= tick_end < m0 + dt` (`driver.py:1075-1085`, reason `"model stale"`; `"model not built"` when no row, `:836`). The ESS gate (`scan.py:1321-1332`, `build_one` returns None, INFO log only) persists nothing, so a gated cycle surfaces as `"model stale"` from the refit-boundary tick on (the previous model's window `[m0, m0+dt)` has just closed).
- **F5 the gated ticks are mostly SKIPPED ticks:** deployed `degraded.mandatory_metrics = [container_cpu_usage_seconds_total]` (`configmap.yaml:366-367`). A model-less cpu ⇒ `handle_solo_request` takes the skip branch (`driver.py:1499-1520`, `record_skipped_tick` call `:1507`; second skip `:1527-1547`, call `:1534`), which writes NOTHING to history (`state.py:583-624`); `complete_scored_tick` (`state.py:626-810`, call `driver.py:1906`) never runs. **R-P6's "derive inside `complete_scored_tick`, zero driver change" would drop exactly the gated ticks.** Writer must sit on BOTH paths.
- **F6 ring:** `solo_pod_scored_history` is pod-level (not per metric), count-trimmed to `_depth_ticks` = `depth_seconds // T` (`driver.py:300-307`, trim `state.py:743-760`): deployed `1d` ⇒ 288 ticks.

## Decisions (D1-D8; each is S-overridable, none touches a protected law)
- **D1 `gate_fired` (code terms):** `1` iff the metric produced no score because its newest model failed the freshness rule: `m["p"] is None and m["reason"] == "model stale"` (F4). This is the code-level surface of the study's gated cycle (ESS < `min_effective_samples`, no model served ⇒ lab `stale_ticks`); `"model not built"` (before the first model; lab `ticks_before_first_model`) is `0`. Honest limit: the same flag also fires for a one-tick build-lag race after a refit boundary and for a counter-representation/policy `"model stale"` (`driver.py:845-846`, `:1074`, one cycle); `stale_hours` and `provenance` make them separable. The ESS of a failed build is only logged ⇒ `ess` NULL on gated rows. Exact attribution needs a marker written by `build_one` (scan.py, pinned) — deferred (Q3).
- **D2 `stale_hours`:** age in hours of the NEWEST persisted model of that (pod, metric) at the tick = `max(0, tick_epoch − model.t0)/3600`; for a scored row that is `model_age_seconds/3600` (< `dt`/3600 = 0.5 h), for a gated row the staleness itself (≥ 0.5 h, grows by `dt` per gated cycle), NULL when no model row exists. Study identities: `stale_ticks = SUM(gate_fired)`, `stale_hours = stale_ticks·T/3600`, `longest_stale_hours` = longest run of `gate_fired=1`. Not `drift_stale` (`state.py` record-only soft flag).
- **D3 other columns:** `p_raw` = the metric's own `m["p"]` (single-metric surprise probability, small = surprising) — NOT the pod-level fused `p_raw` (Q4); `ess` = `m["ess"]` (ESS of the scoring model), NULL when unscored; `provenance` = `model:<m["model_method"]>` when scored, `none:<m["reason"]>` otherwise (closed grammar; unrelated to `solo_window_points.provenance` raw identity and to `provenance_json` calibration).
- **D4 table:** `solo_scored_ticks(pod_key TEXT NOT NULL, metric_name TEXT NOT NULL, tick_epoch REAL NOT NULL, p_raw REAL, ess REAL, gate_fired INTEGER NOT NULL, stale_hours REAL, provenance TEXT NOT NULL, PRIMARY KEY (pod_key, metric_name, tick_epoch)) WITHOUT ROWID` — no second index (M1 lesson); `WITHOUT ROWID` deliberately (−43 % bytes, M3; R-P6 skipped it). One row per configured metric (11) per tick the scorer processed (scored OR skipped; retried/deduped ticks write nothing new). No backfill. Created by a logged `_migrate_scored_ticks()` (P3 precedent: WARNING when a database with history is upgraded, INFO on fresh).
- **D5 writer:** `state.metric_tick_rows(metrics, model_t0, tick_epoch)` (pure) built ONCE in `handle_solo_request` right after `_score_all_metrics` (+ one `state.get_metric_model_t0s(pod_key)` PK-prefix SELECT, 7 µs); passed as **required keyword-only `metric_ticks`** to `complete_scored_tick` and `record_skipped_tick` (P3 precedent: a forgotten value is a `TypeError`, never silent loss) and inserted with `executemany … ON CONFLICT DO UPDATE` inside their existing transaction (no extra commit). `record_skipped_tick` gains the missing rollback-on-error.
- **D6 sweep:** `window_store.sweep_expired_rows(lock, conn, table, cutoff, batch_rows, pause_s, sleep)` — per-(pod, metric) stream, ≤ `batch_rows` per DELETE statement+commit, lock held per statement only, `sleep(pause)` after each batch that deleted rows, never inside a transaction or lock. Runs on its own daemon thread `SoloRetention` (started in `start_solo_runtime`), waking at a MID-TICK instant (`tick boundary + T/2`) every `sweep_interval` — never on the `SoloRuntime`/exporter threads, never at the boundary where ingest and scoring write. A failed sweep logs and retries next interval; one table's failure does not skip the other.
- **D7 YAML (all required, no code default, unknown keys rejected):** `persistence.retention.{raw_points_ttl: 7d, scored_ticks_ttl: 7d, lookback_margin: 12h, safety_factor: 2.5, sweep_interval: 1h, sweep_batch_rows: 2000, sweep_batch_pause_ms: 10}`. Load-time rules: `raw_points_ttl >= safety_factor × (window.Dt + lookback_margin + tick_seconds)` (deployed: 2.5 × 216,300 s = **540,750 s** ≤ 604,800 s; cand-B's 12 h boxcar is `lookback_margin`; max factor today 7 d/2.5035 d = 2.79); `scored_ticks_ttl >= 2 × ring_ticks × tick_seconds` with `ring_ticks = max(1, scored_tick_history.depth // T)` (**172,800 s** deployed ⇒ ≥ 576 ticks per (pod, metric) = 2× the ring); `T <= sweep_interval <= min(both TTLs)`; `safety_factor > 1`; batch rows/pause positive ints.
- **D8 optional S6:** drop the redundant `idx_solo_window_points_key` (M1). Not blocking; P6 never VACUUMs (needs ~2× free space, off the tick thread, operator action).

## Post-review corrections (S, 2026-11-11; RV-P6 + D-S13) — these supersede the text above where they differ
- **D4/D5 retry semantics:** `solo_scored_ticks` keeps the FIRST committed observation per (pod, metric, tick): the insert is `ON CONFLICT … DO NOTHING` (not `DO UPDATE`); a rolled-back transaction leaves no row, so a retry still inserts. Reason (RV-P6 F1): the skip-dedupe marker remembers only the latest skipped tick, a delayed retry re-scores an older tick and used to overwrite an original `gate_fired=1` row. Accepted debt: the pod-level ring/markov state can still be rewritten by such a replay (pre-existing, outside P6).
- **D2 age:** a row's `stale_hours` = scoring-snapshot `model_age_seconds` when present, otherwise `tick − persisted model t0` from a lookup made after scoring, clamped at 0, NULL when neither exists. `gate_fired` is a no-fresh-model PROXY: build lag after a refit boundary, an ESS-gate rejection and a counter-representation/policy `model stale` may look identical; separation and exact cause attribution are not guaranteed. A row's age is not the aggregate `SUM(gate_fired)*T/3600`.
- **D6 schedule:** `next_sweep_epoch(now, T, interval) = ceil((now+interval)/T)*T + T/2` (card sample `1_003_950`); a MINIMUM interval, effective cadence interval+T (3900 s at the deployed values); no guarantee that a large backlog, wake delay or clock jump keeps batches clear of a scoring boundary.
