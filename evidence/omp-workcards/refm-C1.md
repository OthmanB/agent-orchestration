## Decisions (P, binding for C2–C4)
- **D-1 Cadence/horizon**: one inference per production refit (`dt`); context = last `N` grid points ending at `fe`, `N∈{240,5760,11520}` (1 h/1 d/2 d; 2 d = 576 blocks vs STL's 570, stated); `H = horizon_blocks·20 = 260` (13 blocks: served 6…11 plus diagnostic blocks 3 (15 min) and 12 (60 min) from the same call).
- **D-2 Input**: the four continuous RAW series on a regular grid `g_j=origin+15·j` (`origin` = the pod's block origin ⇒ grid idx `j` ↔ block `j//20`, for synthetic AND real). Counter → per-step increment `C(g_j)−C(g_{j−1})` of the linearly interpolated cumulative (identity on a regular grid; telescopes to exact block sums); gauge → linear interpolation. **NaN policy (D8, explicit in YAML)**: grid point whose bracketing raw samples are >`max_gap_seconds` (35.0 = detector `counter_max_gap`, asserted equal to `reference.yaml`) apart, a counter reset inside the bracket, or outside the raw range ⇒ NaN; the MODEL fills NaN (fact 5). The block law keeps running on the ORIGINAL raw samples (`build_blocks`) for every observed/residual block. Modes: multivariate = ONE `(4,N)` call, univariate = four `(N,)` calls (call shape only).
- **D-3 Alignment**: counter context = increments ending ≤ `fe` (idx ≤ 20e), step `h` = increment ending `fe+15(h+1)` (idx `20e+1+h`); gauge context = samples `ts<fe` (idx ≤ 20e−1), step `h` = sample at `fe+15h` (idx `20e+h`) ⇒ block `b` = steps `[20b,20b+20)` for both.
- **D-4 Hand-off** (same block-law semantics): `F[b] = s_c·mean_{steps∈b} q50`; band `Q_τ[b] = s_c·mean q_τ` (mean-of-quantiles = comonotone aggregation, an UPPER bound of the block-mean spread; labelled in C4). `s_c`=1 for gauges; counters `s_c = Σv_b/Σg_b` over the emitted blocks of the cycle's own context (`v` detector block value, `g` mean of that block's grid increments): =1 on regular synthetic grids, ≈16.4/15 on real data (grid increments are rate×15 s, the detector's value is per sample interval). Context-only ⇒ no leakage.
- **D-5 Record** = served-forecast residuals: cycle `c` serves blocks `[e_c+6,e_c+12)`, residual `obs−F`; usable from cycle `c+2` (block ends ≤ `fe_{c+2}`; the `check_no_leakage` equality case). `record(c)` = log entries with block start in `[fe_c−570·T, fe_c)`; an unobserved (NaN) block adds no entry. **Gate**: no model until `(Dt−dt)/T − noise.min_fit_blocks` = 522 served blocks are usable = 88 cycles (the STL cold record size), derived from `reference.yaml`, not retyped.
- **D-6 Timeline** (`cycles.py` computes it): first cycle `n0=ceil((ctx_blocks+7)/6)·6` = 24 / 300 / 588; first scored `k+1=n0+528+2` = **554 / 830 / 1118** (own-first). C uses ONE first cycle (588, the 2 d context) for all contexts ⇒ one record start and the **common valid set `k+1 ≥ 1118`** (< display start 1296; first event onset ≥1332 ⇒ ≥214 valid quiet ticks, settling baseline ≥48 holds). 215 cycles per 1872-tick run. `t0` is an ABSOLUTE multiple of `dt` (as `stl_lite.py:374`): synthetic origins are multiples of `dt` (above), a real pod's origin is not, so its first cycle can sit up to 5 blocks later (190–191 cycles per 1728-tick slice; first scored tick 1118…1123, computed per pod by `first_valid_tick(…, origin)`).
- **D-7**: reference = p50 (Part 2 §3); its skew bias is visible in A1c `bias`. Rare-count metrics keep their own cycle clock (first model k+1=582, A1a `RareCountProvider`), so with K=11 the eligible set at ticks 1116–1117 is rare-count-only until the continuous ring fills; the common offset 1118 (= first TimesFM model + 2 ring ticks, the rule behind A1c's 584) excludes those ticks; E records the measured first scored `k+1`.
- **D-8 ESS gate (D14)**: (a) production skips a metric's cycle when the Bartlett ESS of the fit-window BLOCK values is below `undersampling.min_effective_samples` = 36 (`prod: scan.py:1320-1332`; lab `StlLiteProvider._cycle` reason `ess_gate`, `noise.min_effective_samples`); this lives in the STL-lite FIT path, NOT in the downstream chain. `TimesFmProvider` has no window fit, hence NO gate: it serves a forecast every cycle, so every tick ≥ the common offset with an observed block is scored (STL as deployed on S1 seed 1: 732/1872 scored, 47.7 % of `p_raw` >0.2, A1c 2.4). (b) `ess[k]` of the TimesFM run is INFORMATIONAL only: Bartlett ESS (A1a `bartlett_ess`, `noise.bartlett_max_lag`) of the emitted block values of the production window `[fe−570·T, fe)` of the serving cycle (NaN if <2 blocks); it never gates and never changes a forecast; C3 reports the share of served cycles whose window the deployed gate would reject. (c) C3 therefore reports STL-lite twice — `stl-gate-on` (as deployed = the Part-1 yardstick) and `stl-gate-off` (`dataclasses.replace(cfg, noise=dataclasses.replace(cfg.noise, min_effective_samples=0))` on the lab `RefConfig`, `reference.yaml` untouched, analysis-only) — on ONE model-independent tick set (C3 D-1/D-6).
