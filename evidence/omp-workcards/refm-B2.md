B2 implements one admission gate with both policies: `on_full: block` (arrivals wait outside the pipeline) and `on_full: drop` (production). Scan tick 300 s, refit 1800 s.
6. ⚠ **Batching facts (P read the installed `timesfm3` 3.0.2 and probed CPU torch)**: (a) valid batching is along the batch axis: `predict_batch([ (V,T) … ])` requires the same V in every context (else ValueError), pads each chunk to its max context (equal T ⇒ none), chunks of `forecaster.config.per_core_batch_size` (default 4; mutable non-frozen dataclass, both backends), one `model.decode` per chunk. CPU probe, 5 pods (V=3,T=2880): batched vs 5 single calls max|Δ| = **0.0**; (b) **variate packing is INVALID**: 5 pods×3 series in one V=15 call differs from separate calls by 0.054 (input ptp 8.44) because variate attention mixes pods (the masking risk of Part 2 Q3); (c) ⚠ **MLX does not batch multivariate pods**: `timesfm3/mlx/timesfm3_forecaster.py:251-309` loops one series at a time for V≥2 and batches only all-1-D inputs, so `batched_overlap` is expected to equal `overlap` on MLX — the probe decides (`min_gain`); (d) A2's `max_variates 32` chunking (`TimesFM3Evaluator`, `_MAX_VARIATES_PER_FORWARD`) is for >32 variates in one set, not used; (e) `predict_batch` runs `gc.collect()` per call (GIL).
7. **Measurement budget (P)**: a pass at its own knee lasts the budget, so a 1.3×300 s grid per variant×context×device would cost >10 h. Instead: (a) calibrate `T(N)=a+s·N` from two small passes, (b) measure grid points whose predicted wall = `grid.target_pass_wall_s` (≤240 s ⇒ the 120 s and 180 s knees are measured to ≥1.3×), (c) the 300 s knee is `extrapolated_linear` through the measured throughput and **validated by one sustained staggered run per device** (a full 300 s tick at ρ=1.3, which also exposes thermal drop-off: `sustained_ratio`), (d) beyond-measured values are always flagged `extrapolated`. S may append 390 to `target_pass_wall_s[11520]` for a fully measured 300 s knee (+≈6.5 min per variant).
8. **Arrival model (YAML)**: `burst` (all pods ready at t=0 = "scan starts when the last point arrives") for PASS runs; `stratified_uniform` over `window_s` for STAGGER/VALIDATE runs (pod i arrives uniformly inside stratum `[i·W/N,(i+1)·W/N)`, seeded). Unbounded queue growth = backlog (arrived−done) at window end > `unbounded_end_backlog_frac` of N; scale-invariance (ρ=N/(μ̂·W)) turns a 60 s window result into the 300 s-tick pod count `ρ*·μ̂·300`, confirmed by the validate run.
9. **Power scopes differ** (as B1): Mac whole-system `SystemLoad` (coarse; unresolved when pass < 30 s), CUDA GPU board only; energy = ∫(P − idle)dt over the pass window, idle interpolated between the block's before/after baselines; `ExternalConnected` recorded (Mac must be on AC; it was on battery at planning).
10. **Virtual pods from the 10 real ones** (`podgen`): virtual pod `k` → source pod `k % n_src`, cycle `c=k//n_src`, window start `(c·shift_stride_samples + pass·pass_shift_samples) mod (L−T+1)` (`L` = shortest series of that pod; ≈51.5 k samples, so ≈16 distinct shifts at T=11,520 ⇒ ≈160 distinct windows, then windows wrap — recorded as `unique_windows`), plus a seeded per-`k` affine perturbation `x·(1+perturb_rel·u1)+perturb_rel·u2·mean|x|` (`default_rng([seed,k])`) so every pod's tensor is distinct. Counters (cpu, rx_bytes, tx_bytes) are fed as per-sample increments (`v−v_prev`, `v` after a reset: the detector's counter law), mem raw; this is compute-realistic input, NOT the accuracy path (C/A1a own blocks). No cache effects exist on the model path (no KV cache; each decode is single-shot).
